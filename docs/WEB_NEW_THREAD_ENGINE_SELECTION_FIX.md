# 网页新建对话跟随侧栏模式选择

## 问题与分类

左侧 Codex / Claude 图标只影响列表筛选，新建对话仍取当前面板的引擎，导致在 Codex 对话里选择 Claude 后，新建的仍是 Codex。

本次属于修复（PATCH），目标版本 `0.103.3-dev.1`：修正已有新建入口的模式来源。Android 只同步版本名称，不生成安装包，`versionCode` 保持 `408`。

## 实施步骤

1. 新建对话模式按“显式指定模式 → 左侧选中模式 → 所在面板模式”取值；初始未选择任何模式时沿用默认 Codex。取消筛选后继续沿用所在面板模式。
2. 输入框的新建按钮、面板内的新建入口共用上述模式选择；按钮提示及 Claude 不可用状态按实际将创建的模式显示。
3. 保持点击筛选图标仅更新列表和后续新建模式，当前已打开的对话继续使用自己的引擎；主动切换引擎时仍以明确指定的目标为准。
4. 同步版本和更新概述，进行生产构建、Python 版本文件编译和差异检查；不新增或运行测试，本地提交，不推送。

## 检查要点

- 当前聊天为 Codex，选中 Claude 后新建应发送 `claude-code`；反向同理。
- 没有筛选时保持面板模式；新建后的模型、思考和授权偏好使用目标模式对应的字段。
- Claude 不可用时，选中 Claude 的新建按钮被禁用；目标为 Codex 时不受该状态影响。
- 桌面和移动端共用新建入口，已打开的并发窗口不因筛选变化而切换引擎。
