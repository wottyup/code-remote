# Android 局域网检查与下载更新

## 需求与分类

当前设置页通过 GitHub Releases 检查版本，发现新版本后只打开发布页。改为使用手机当前连接的 Code Remote 电脑地址，在本机内网检查并下载已构建的 Android 安装包，随后交给 Android 系统安装。用户因此能直接从 App 下载更新，属于新增功能（MINOR）。目标版本 `0.104.0-dev.1`，`versionCode 417`；如为实际升级链路另建验收包，则使用 `0.104.0-dev.2`、`versionCode 418`，保留两个安装包。

## 实施步骤

1. 在 `4173` 网页服务中加入 Android 更新清单和安装包下载接口，向现有后端核验配对凭据。清单从本项目 `artifacts` 中选择版本最高、命名符合约定的 debug APK；下载接口只接受符合命名规则的本项目文件，不允许任意路径。清单禁用缓存。Android 使用当前已保存的连接地址与配对凭据访问，不固定某个可能变化的 IP。更新网页服务时保留正在运行的后端对话进程。
2. 设置页“检查更新”读取局域网清单，与当前 `versionName` 比较；有新版本时显示下载操作。使用 Android 下载管理器保存 APK，展示下载通知，下载完成后可打开系统安装界面。处理网络、下载及安装授权失败，并补齐中英文文案。
3. 更新 Android 版本与简短版本记录。构建并单独保存 APK；按发布顺序先装 `dev.1`，再发布 `dev.2` 用于验证发现新版本、下载和覆盖安装。不可覆盖历史 APK，不推送 GitHub。
4. 在手机上验证局域网清单、更新发现、下载完成和安装结果；记录能确认的实际范围。本地提交修改，清理调试进程与临时脚本。

## 约束

- 只提供本项目 `artifacts` 中符合版本命名的 APK，不把工作区或其他项目文件暴露出来。
- 后续每次完成 Android 打包，应把新 APK 以约定文件名保存进 `artifacts`，才能被检查更新发现。
- 系统安装仍需用户在 Android 安装界面确认；首次安装可能要求授予“安装未知应用”权限。

- `0.104.0-dev.1`（`versionCode 417`）已覆盖安装到 `10.126.126.2:5555`，设备上的原有连接配置保留；`0.104.0-dev.2`（`versionCode 418`）独立构建并保存，两个包的签名证书一致。
- `4173` 网页服务已加载更新接口，未配对请求返回 401；已配对请求返回 `dev.2` 清单与 APK，完整下载字节数和 SHA-256 均与清单相符；无关文件与路径穿越请求返回 404。后台聊天服务未重启。
