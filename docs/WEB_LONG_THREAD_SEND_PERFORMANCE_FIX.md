# 长对话排队启动延迟与历史收起

## 目标与分类

长对话中上一轮回复结束后，排队消息不应因核对完整历史而等待很久；网页默认只显示最近 10 轮，旧消息可按需展开。属于修复 / PATCH：排队和查看历史的能力不变，改善发送等待和页面负担。目标版本 `0.104.1-dev.1`；不生成 Android 安装包，`versionCode` 保持原值。

## 实施步骤

1. 追踪回复完成通知、队列唤醒、上一轮完成核对及真正发送的路径，定位长对话的等待来源。
2. Codex 忙闲查询直接读取运行时状态，队列核对仅读取最近轮次；Claude 常规核对只提取最后一条回复状态。特殊情况下保留完整历史回退，确保中断、未确认送达和顺序规则不变。
3. 网页默认显示最近 10 轮，提供继续展开旧消息的入口；旧消息仍保留在历史中，不修改 AI 上下文。
4. 更新版本号和简要版本历史；构建网页并检查差异。不新增或运行测试。
5. 仅暂存本次修改并本地提交，不主动推送。

## 验收要点

- 回复完成后，排队核对的常规路径不再读取完整长对话；Codex 忙闲查询也不先扫描本地历史。
- 旧消息默认收起，可继续展开；消息本身和 AI 上下文不被删改。
- 正常发送、排队、暂停和回执丢失时的恢复逻辑保持原样。
- 网页构建通过，提交中不包含临时调试产物。
