# Android 桌面与安装界面图标比例分离

## 问题与分类

`0.106.0-dev.1` 为缩小安装界面图标，将共用自适应图标的前景留白由 `18dp` 改为 `29dp`，导致桌面 Logo 同时缩小。此次属于修复 / PATCH：恢复原有桌面入口的显示比例，用户能力不变。目标 Android 版本 `0.106.2-dev.1`，`versionCode 422`。这是小幅视觉修正，不单独写入 CHANGELOG。

## 实施步骤

1. 将桌面自适应图标前景恢复为此前已校准的 `18dp` 留白。
2. 为安装及应用信息界面建立独立的应用图标资源，沿用 `29dp` 留白。
3. 在清单中分别指定 application 图标与桌面入口 MainActivity 的图标；启动页继续使用现有独立启动图标。
4. 编译并核对 APK 中的两组图标和清单；生成独立文件名的新包，覆盖安装到已连接手机，在手机状态允许时检查桌面实际效果。
5. 记录验证结果，只提交本次修改到本地 Git。

## 验收关注点

- 桌面 Logo 恢复到 `0.106.0-dev.1` 之前的比例。
- 安装界面图标与桌面入口引用不同资源，后续比例调整互不牵连。
- 系统启动页继续引用专用启动资源。
- 历史 APK 保留，应用 ID 与已有数据不变。

## 完成与验证

- 桌面前景恢复 `18dp` 留白，新增采用 `29dp` 留白的 `ic_package` 资源；application 使用 `ic_package`，MainActivity 桌面入口显式使用 `ic_launcher`。
- `:app:assembleDebug` 与 `git diff --check` 通过。已核对最终 APK 的应用图标为 `ic_package`、桌面活动图标为 `ic_launcher`；启动页专用资源引用保持独立。
- 已覆盖安装到 PJZ110，系统版本为 `0.106.2-dev.1`（`versionCode 422`）。手机当时已在桌面，通过实际桌面截图确认现有快捷入口的 Logo 已放大，主体没有触碰或超出白色底板边界。
- 新 APK 为 `artifacts/code-remote-android-0.106.2-dev.1-debug.apk`，SHA-256 为 `32e2cacbeb871c411166032a250cb52953d4aa92ab7115df916e34e74feac529`。历史包未覆盖。
