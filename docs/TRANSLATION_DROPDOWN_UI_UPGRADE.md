# 翻译设置下拉菜单界面升级

## 需求与版本

体验优化（PATCH），目标版本 `0.97.3-dev.5`。翻译模块当前使用浏览器原生 `select`，展开菜单的外观受操作系统控制，主题配色和选中反色难以稳定呈现。升级翻译模块内的五处下拉界面，不改变选项值、配置保存或切换逻辑。

## 开发步骤

1. 新建可复用的翻译设置下拉组件，显示当前值、展开箭头、选中标记与主题化选项列表；五处现有 `select` 统一替换。
2. 使用浏览器顶层弹出层避开设置卡片裁剪；根据视口空间在控件上方或下方定位，滚动和窗口变化时保持对齐。
3. 支持点击外部和 Esc 关闭，方向键、Home/End、Enter/空格操作选项，并保留焦点提示与禁用状态。缺少弹出层支持时使用原生选择框。
4. 用现有主题色变量绘制触发按钮和选项，选中及悬停状态使用清晰反色；兼顾窄屏与长选项名称。
5. 更新内部版本和简短版本历史，执行网页构建和差异检查，仅提交本次文件到本地仓库。

## 验收要点

- 翻译方式、翻译引擎、配置选择、账户类型及协议切换的下拉外观一致。
- 菜单在黑白、暖色、复古、像素、中国复古和自定义主题下可读，展开时不被卡片或视口裁剪。
- 鼠标、触屏和键盘均可完成选择；选项值和原有操作结果不变。

## 共享下拉背景修复（0.102.1-dev.1）

Codex／Claude 配置页复用了此组件，但菜单颜色变量仍限定在 `.translation-settings` 内，导致新位置的弹层背景、文字与选中样式使用未定义变量，背景透明并与下层内容重叠。本次为修复（PATCH），恢复已有菜单的正常显示。

1. 将菜单颜色变量及各主题覆盖统一放到 `.theme-settings-panel`，使翻译、配置选择、接口协议和密钥方式下拉均能继承。
2. 保持现有不透明菜单底色与选中反色，同步覆盖原生选择框的兼容路径。
3. 同步补丁版本及简短版本历史，构建前端并检查差异后本地提交；无需重启后端，不推送远程。
