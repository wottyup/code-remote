# 网页聊天翻译功能开发

## 需求与版本

新增功能（MINOR），目标版本 `0.93.0-dev.1`。网页输入中文时，可在输入框上方预览自然美式英语译文，并只把英文译文发送给 Codex 或 Claude Code。AI 回复的英文由后端翻译成中文显示，保留查看英文原文。翻译引擎可选 Google Cloud Translation、Microsoft Translator、DeepL API、Codex、Claude Code，以及兼容 OpenAI Chat Completions 的接口。仅处理文字，不提供语音朗读。

## 开发步骤

1. 后端实现统一翻译接口和六种引擎适配。接口密钥只保存在服务器权限受限的配置文件中，读取配置不返回密钥；请求设置超时、长度上限，返回明确错误。AI 翻译使用独立临时会话，不写入聊天历史；Claude Code 禁用工具，Codex CLI 关闭命令工具与网页搜索，并在临时目录以只读沙盒运行。
2. 翻译接口区分中译英和英译中。AI 引擎收到自然美式英语或清晰中文的翻译指令；代码块、链接、路径等内容尽量保留。缓存相同文本和配置的结果，减少输入预览的重复计费。
3. 设置页提供翻译开关、引擎选择和相应配置项。浏览器只保存开关与引擎选择，服务器保存接口密钥；配置状态可查看，密钥不能回显。
4. 输入框上方显示延迟更新的英文预览。发送、定时发送和排队入口在发送前取得当前草稿的译文；翻译失败时保留草稿且不发送，避免旧预览或中文原文误发。
5. 聊天中的英文 AI 正文完成后显示中文译文，保留英文原文入口；流式回复、工具记录、结构化选项和代码内容不得被覆盖或误改。历史消息重新打开时可再次获取译文。
6. 更新版本及简短更新记录。完成构建与静态检查，只提交本次文件到本地仓库；没有用户明确命令时不推送 GitHub。

## 交付边界

普通翻译 API 不保证美式语气，Codex、Claude Code 和 Chat Completions 引擎通过翻译指令改善表达。实时预览受网络和模型速度影响，不保证逐字零延迟。回复翻译应在英文正文完成后显示，避免逐 token 翻译导致闪烁和费用暴涨。
