# 已登录 SSH 终端交给 AI 接管

## 分类与目标

这是新增功能（MINOR）：用户手动在网页终端完成 SSH 登录后，可把当前聊天对应的终端交给 Codex 或 Claude 操作，之前无法完成这一交接。目标版本 `0.91.0-dev.1`。

目标是复用已经登录的终端会话，不保存或转交 SSH 密码。AI 的命令和输出实时留在同一个终端画面；工具结果也进入当前聊天的操作记录。用户可随时收回控制。当前先支持使用 tmux 持久终端的 Linux 实例；Windows 的 PTY 没有可跨进程接入的会话，此入口应明确不可用。

## 实施步骤

1. 在后端增加按聊天绑定的终端接管代理。用户显式开启后才接受 AI 工具调用；代理检查对应 tmux 会话仍存在且前台进程为 SSH。提供读取画面、发送单行命令、发送中断键的能力，限制输入与输出大小。接管期间保护该 tmux 会话，不让闲置清理器回收。
2. 增加通过本地 Unix socket 与代理通信的 MCP 工具，并在 Codex 的聊天创建/恢复及 Claude 的每轮启动时注册。工具上下文只绑定当前聊天，不传 SSH 凭据或网页配对令牌；未接管的聊天调用必须拒绝。
3. 增加查询、开启和收回接管的已配对 API。在网页终端顶部加入状态和按钮。仅聊天绑定的 Linux 持久终端可开启；失败时给出可读提示。重新打开终端后从服务端恢复状态，收回后 AI 工具停止操作。
4. 将终端工具调用的命令及输出摘要显示在当前聊天的操作记录中，同时保留终端实时输出。长输出限制展示长度，不能把 SSH 密码作为工具参数发送。
5. 更新版本及简短版本记录，构建网页，检查变更范围，只提交本次文件到本地仓库。

## 边界

- 接管只复用远端账户已有权限，不提升权限；需要二次密码或验证码时，先由用户收回控制并在终端输入，再重新接管。
- 终端画面和工具结果可能包含远端输出中的敏感信息，应按现有聊天记录的可见性处理。
- AI 进程与网页后端仍以同一宿主机账户运行；本功能的接管开关是产品控制，不构成对同账户进程的安全隔离。
