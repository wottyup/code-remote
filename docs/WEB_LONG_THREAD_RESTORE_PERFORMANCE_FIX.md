# 网页长对话刷新恢复性能修复

## 目标与分类

刷新网页恢复长对话时，缩短首屏等待和完整历史同步的耗时，保持消息、图片、模型与思考等级、排队消息和多窗口状态的原有行为。本次属于修复 / PATCH：用户原有任务不变，改善长对话加载速度。目标版本 `0.103.5-dev.1`；不生成 Android 安装包，`versionCode` 保持原值。

## 已确认的耗时路径

- 网页每次合并完整历史时，`preserveCurrentImages` 对每条新消息反复扫描旧消息；长对话的匹配次数呈平方增长。
- 首次恢复持久化缓存前，`restoreActiveThread` 等待对话列表刷新；列表网络请求会拖延本地缓存上屏。
- Codex 历史投影的紧凑读取对每个未缓存条目单独发起 SQL 查询；后端还会在历史文件每次追加后重新扫描整个 JSONL 文件以提取模型和思考等级。

## 实施步骤

1. 为网页消息合并建立按 ID、轮次和文字索引，保留原先的匹配优先级与相同文字图片的消费顺序。
2. 让本地持久化历史与对话列表并行读取；缓存可用时先展示，再依据最新列表决定是否同步服务器历史。
3. 将 Codex 历史投影中的未缓存条目改为批量查询，并使模型与思考等级元数据在同一文件追加时从上次完整记录的偏移量继续读取；文件替换、缩短或原地等长改写时仍完整扫描。
4. 更新网页、服务端版本和简短版本记录；构建网页并检查差异，仅提交本次文件到本地 Git，不推送远端。不新增或运行测试。

## 验收要点

- 刷新长对话时，本地历史显示不再等对话列表请求完成；后台仍核对服务器最新历史。
- 相同 ID、同轮内容和重复文字图片按原有规则关联，不丢失已缓存的消息元数据。
- Codex 历史投影以固定大小批量读取未缓存条目；历史追加后只扫描新增记录，文件替换、缩短或原地等长改写能重建元数据。
