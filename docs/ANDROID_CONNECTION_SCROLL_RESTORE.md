# Android 切换连接后的聊天滚动恢复

## 需求与分类

从位于底部的聊天切换到另一电脑连接，再切回来时，如果聊天正在收到回复，应保持在最新消息底部。现有自动跟随行为未按预期工作，归类为修复（PATCH）。目标 Android 版本 `0.106.1-dev.1`、`versionCode 421`。

## 实施步骤

1. 梳理连接切换、会话恢复、磁盘缓存和服务器历史刷新时的消息渲染与滚动顺序。
2. 限定异步滚动回调只操作创建它的连接、会话和视图，避免旧连接回调移动新页面。
3. 会话恢复期间保留“回到底部”的意图；等消息列表完成布局后滚动到底部。用户主动上滑时取消该意图。
4. 检查差异，编译并生成独立 APK；记录版本、本地提交，不推送 GitHub。

## 验收关注点

- 切换连接后恢复正在回复的聊天，初始缓存和网络历史更新均落在底部。
- 旧连接的延迟回调不能改变新连接的滚动位置。
- 用户手动上滑阅读时，后续刷新不会强制拉回底部。

## 实施与验证

- 已给恢复聊天的滚动回调加连接、会话、视图及触摸轮次校验；初次恢复时在消息列表布局完成后滚到底部，并在用户主动上滑后停止跟随。
- `:app:assembleDebug` 与 `git diff --check` 通过；APK 完整性和版本字段已核对。
- `0.106.1-dev.1`（`versionCode 421`）已覆盖安装到已连接的 PJZ110 手机上。安装时手机正在使用其他应用，未打断当前操作做连接切换交互复测。
