# 已保存翻译配置切换协议时保留参数

## 需求与版本

体验优化（PATCH），目标版本 `0.97.1-dev.1`。目前“翻译引擎”切换只会打开目标引擎的配置列表，用户要把已保存的 Chat Completions、OpenAI Responses 或 Anthropic Messages 配置改成另一协议时，必须重填地址、模型和密钥。增加当前配置的协议变更操作，保留这些参数并明确区分“切换使用哪组配置”和“修改当前配置的协议”。

## 开发步骤

1. 服务端新增原子迁移接口，仅允许上述三种 AI 接口协议之间迁移。合并当前表单修改，连同仅保存在服务端的密钥移动配置；旧协议至少保留一套空配置，目标协议已有同名配置时生成不重复的名称。保留原有配置文件格式和权限。
2. 迁移时把完整的 `/chat/completions`、`/responses` 或 `/messages` 端点地址还原为 API 基础地址，避免新协议拼接出错误路由。协议是否真正可用仍由连通性试译确认。
3. 设置页给当前配置增加“更改协议”选择和操作；在用户直接切换到另一 AI 协议时，也提示可沿用刚才已保存的配置。成功后选中新协议中的迁移配置，更新本浏览器的配置 ID，清除密钥输入草稿并显示结果；通过“更改协议”操作提交时，当前表单修改也随迁移提交。
4. 更新版本与简短版本历史，完成静态检查和网页构建，只提交本次文件到本地仓库。按空闲重启流程激活后端更新。

## 边界

切换“翻译引擎”仍用于选择该引擎已有配置，不自动改动服务端配置。迁移不会验证目标路由；跨不同服务商时，用户可能还需调整地址、模型或密钥。
