# 终端接管误判手动输入修复

## 目标与分类

用户未输入文字时，AI 终端工具不应被“用户仍在终端手动输入”长期拦住。终端的鼠标、焦点及设备状态上报仍应送到 tmux/SSH，但不能作为未提交的手动输入。属于修复 / PATCH，目标版本 `0.104.2-dev.1`。

## 实施步骤

1. 核对网页终端输入、WebSocket 和接管锁的路径，确认哪些终端控制序列会误触发无限期手动输入锁。
2. 在服务端识别纯终端协议上报，让它们正常转发而不设置手动输入锁；键盘和粘贴输入继续受保护，并保持命令与输入的串行顺序。
3. 保留用户输入文字后直到回车或 Ctrl+C 的保护；明确真正未提交输入时的错误提示。
4. 更新版本与简要版本历史，静态检查差异；不新增或运行测试。
5. 仅暂存本次修改并本地提交，不主动推送，也不在当前对话中重启后端。

## 验收要点

- 仅点击、滚动或聚焦终端，不会让 AI 终端工具长期等待。
- 输入密码或命令但未提交时，AI 仍不能把命令插入该行；提交或 Ctrl+C 后可继续。
- 终端协议上报仍到达当前会话，且不记录用户输入内容。
