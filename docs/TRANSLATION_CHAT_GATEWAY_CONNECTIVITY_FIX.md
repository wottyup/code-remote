# Chat 翻译协议连接网关失败修复

## 诊断与版本

修复（PATCH），目标版本 `0.97.2-dev.1`。现有 Chat Completions 请求使用 `urllib` 默认的 `Python-urllib` 标识，当前用户网关对它返回 HTTP 403；同一密钥、模型和 `/v1/chat/completions` 地址改用应用标识时返回 200。用户只填主机根地址时，旧实现拼成 `/chat/completions`，当前网关返回 404；其 `/v1/chat/completions` 路由可用。

## 开发步骤

1. 服务器翻译请求统一发送明确的应用 `User-Agent`，保留现有超时、响应长度限制和密钥不出现在错误与日志中的约束。
2. Chat 协议接受完整 `/chat/completions`、`/v1` 基础地址和主机根地址。根地址优先使用标准 `/v1/chat/completions`；为兼容旧网关，只有标准路由返回 404 时才尝试根路径 `/chat/completions`。
3. 上游 HTTP 错误按 401、403、404、429 给出不含上游原文和密钥的明确提示。设置页说明可填写根地址、`/v1` 或完整端点。
4. 更新版本与简短版本历史，完成静态检查和网页构建，只提交本次文件到本地仓库。按空闲重启机制激活后端更新。

## 边界

网关仍须支持所填模型和 Chat Completions 路由。若网关本身拒绝该密钥或路由，应用不会绕过其权限限制。

## 完成记录

使用当前已保存的接口配置，不输出密钥或译文，分别通过 Chat 和 Responses 协议完成了一句试译。Python 语法检查、网页构建和差异检查通过。
