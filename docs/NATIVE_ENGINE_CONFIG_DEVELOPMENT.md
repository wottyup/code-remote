# 网页配置本机 Codex 与 Claude API

## 需求与分类

设置页提供 Codex 和 Claude Code 的 API 地址、密钥表单。Codex 写入当前服务使用的用户级 `config.toml`，建立专用 Responses 提供方并设为默认；Claude Code 写入 `settings.json` 的 `env`，支持 `ANTHROPIC_AUTH_TOKEN` 与 `ANTHROPIC_API_KEY` 两种凭据方式。保留与这几个 API 字段无关的配置；前端只接收密钥是否已配置，不接收已有密钥明文。保存后本机 CLI 读取同一文件；Codex App Server 在没有运行中任务或请求时重新连接以应用配置，忙碌时提示稍后重载。

Codex 的密钥写入只限本机账号可读的配置文件，使用 CLI 官方支持的 `experimental_bearer_token` 字段；该字段是明文存储，拥有同一系统账号文件读取权限的程序仍可读取。仅保存配置不等于接口和模型连通性验证。

配置依据：[Codex 自定义提供方](https://developers.openai.com/codex/config-advanced)、[Codex 配置字段](https://developers.openai.com/codex/config-reference)、[Claude Code 网关连接](https://code.claude.com/docs/en/llm-gateway-connect)。

这是新增功能（MINOR）：用户以前不能从网页直接管理本机两种引擎的原生配置。目标版本 `0.101.0-dev.1`。本次不生成 Android 安装包，`versionCode` 保持 `408`。

## 实施步骤

1. 增加固定路径的配置读取、API 字段更新和原子保存能力，使用文件摘要避免覆盖外部更新，并限制文件大小；Codex 的托管配置块和原有 TOML 其他段落保持独立。
2. 增加仅供已配对设备使用的读取、保存与 Codex 重载接口；配置响应禁止浏览器缓存，已有密钥不返回网页或写入日志。
3. 设置页增加 Codex、Claude Code 两个表单入口，显示实际路径、地址、密钥状态、保存和重载状态；仅在打开对应入口时读取配置摘要。
4. 同步版本名与简要版本历史，构建网页并检查差异，本地提交，不推送远程。

## 验收要点

- 网页可配置本机 Codex Responses API 和 Claude Messages API 地址及密钥，已有密钥只显示“已配置”。
- 原有非 API 配置保留；无效 TOML/JSON、过大内容或文件在页面编辑期间被其他程序修改时不会覆盖原文件。
- 保存使用原子替换；新 Claude 进程读取新配置，空闲 Codex 连接重新加载，忙碌时明确提示稍后重载。
- 设置页切换或关闭后不把密钥留在浏览器持久存储中。

## 多配置与模型管理（0.102.0-dev.1）

### 需求和边界

Codex、Claude 分别保存多套具名配置，可编辑、删除、测试、保存及应用。密钥仅保存在服务端私有文件和本机 CLI 配置中，网页只获得是否已填写的状态。首次读取兼容此前的单配置。编辑配置不会立即更改正在使用的配置；“保存并应用”才更新本机 CLI。应用当前正在使用的配置也支持更改地址、凭据和模型，不要求重复填写已有密钥。

Codex 增加默认模型和协议字段；Claude 增加默认模型以及 Sonnet、Opus、Fable、Haiku 的显示名称和实际请求模型映射。映射同步到 Claude 原生环境变量，网页模型列表同步显示名称。接口类型以 CLI 实际支持为准：Codex 为 Responses，Claude 为 Anthropic Messages，不把不受支持的协议写成可用配置。连通性使用表单草稿发起短模型请求，Claude 检查填写的映射模型并对相同模型去重；不会改变当前应用配置。

这是新增功能（MINOR）：用户可管理多套服务商配置、指定模型映射并直接检查接口。目标版本 `0.102.0-dev.1`，不生成 APK，Android `versionCode` 保持 `408`。

### 实施顺序

1. 扩展原生配置读写，保留无关字段并写入模型和 Claude 角色映射。
2. 增加服务端多配置存储与迁移、配置修订冲突检查、保存/删除/应用和连通性接口。禁止重定向传递密钥，限制请求超时和响应大小，错误中不返回上游原文或凭据。
3. 设置页使用品牌图标、配置选择器、分组表单、协议选择器及模型映射表；支持窄屏和现有主题，保护未保存草稿。
4. 聊天模型选择读取生效配置的模型和显示名称，确保自定义模型能用于实际请求；应用配置后刷新模型选项。
5. 同步版本历史，构建前端，检查代码差异并本地提交；不推送远程。后端更新需要重新加载进程，避免中断已有任务和终端。

### 补充验收要点

- 新增配置不会复用其他配置的密钥；编辑或切换同一配置的凭据方式时可保留其密钥。
- 保存备用配置不会修改 CLI；正在应用的配置不能直接删除，必须先切换到另一配置。
- 配置文件外部变更时拒绝覆盖，界面提示重新读取。
- 测试结果明确区分认证、地址/协议、模型、限流和网络错误；成功代表模型返回有效响应。思考模型因短测试的输出上限提前结束时明确说明，避免把成功接收请求误报为连接失败。
- Claude 四种角色的显示名与请求模型分别保存，空白映射恢复该角色的 CLI 默认。
- 仅输出配置摘要，浏览器持久存储和日志均不包含密钥。

### 实施说明

- 每个引擎最多保存 30 套配置，保存在服务数据目录的私有文件中；导入此前本机配置后，第一次保存时建立配置库。
- 协议下拉显示各协议的支持范围；本次实现 Responses 和 Messages 的原生配置，Chat 等跨协议转换尚未实现，相关选项不可选。
- Claude 使用官方 `ANTHROPIC_DEFAULT_{角色}_MODEL` 和对应 `_NAME` 环境变量，同时保留聊天中手动选择的优先级。依据：[Claude 模型配置](https://code.claude.com/docs/en/model-config)。
- Codex 自定义模型加入现有模型列表，应用后更新当前输入框和新对话的默认模型；其他已有对话的手动模型选择保留。配置变更通过全局通知同步到已连接网页。
- 只保存配置时不修改 CLI；若保存成功但 CLI 文件更新失败，返回“已保存、未应用”的明确结果，避免重复新增配置。
- 完成前执行前端生产构建、Python 编译及差异检查。本次未运行自动化测试或使用现有密钥向上游发起请求。

## Claude 模型名称自动填写（0.103.1-dev.3）

用户希望填写右侧实际请求模型时，左侧显示名称跟随变化。本次属于体验优化（PATCH），减少同一模型名称的重复输入，不改变模型配置能力。

1. 编辑任意 Claude 角色的实际请求模型时，同步填写该行显示名称；清空时一并清空。显示名称沿用 80 字限制，实际模型 ID 保留完整内容。
2. 显示名称仍可手动修改；读取或切换已有配置时保留已保存的显示名称。表单提示说明自动同步的行为。
3. 执行前端生产构建、差异检查并本地提交；这次细节调整不单独追加版本历史条目，不生成 Android 安装包，无需重启后端。

完成结果：四个角色的实际请求模型输入均会同步显示名称，显示名称仍可单独编辑，原有配置读取逻辑保持不变。`pnpm --filter code-remote build` 和 `git diff --check` 已通过，刷新网页即可使用。

## Claude 配置实际应用核查

用户要求确认网页中的 `mercury-3` 是否已覆盖本机 Claude 配置。只读检查发现：已保存配置为 Chat 协议的 `mercury-3`，但当前生效配置未匹配任何已保存配置，`/root/.claude/settings.json` 仍使用 `gpt-6sol`。运行后端已加载协议转换接口。

1. 使用现有连通性检查核对用户指定的已保存配置，只输出状态和模型，不输出凭据。
2. 连通后通过配置服务应用该配置，沿用修订检查和已有密钥保留机制，读回默认模型、角色映射与当前生效配置编号。
3. 使用本机配置对应的原生 Messages 入口核对转换链路；根据实际结果判断是否需要修改代码。检查不重启服务或中断运行中的对话。

核查结果：用户指定的已保存配置通过上游连通性检查；通过现有配置服务应用后返回 `applied=true`、`changed=true`，当前生效配置编号为 `local`。读回 `/root/.claude/settings.json`，默认模型及 Sonnet、Opus、Fable 的请求模型和显示名称均为 `mercury-3`。本机 Messages 转换入口的实际请求成功，模型菜单读回“本机默认 · mercury-3”和对应映射。Haiku 沿用用户保存的空白映射。

结论：此前配置已保存在配置库但未生效到 CLI；此次完成配置修复（PATCH），已确认现有应用写入和转换链路正常。没有应用代码变更，无需构建或重启，也不发布新版本；刷新网页即可读取生效模型。后续切换配置使用“保存并应用”，“保存配置”仅更新配置库。
