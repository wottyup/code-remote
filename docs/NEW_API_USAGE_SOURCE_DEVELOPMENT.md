# Token 用量查询接入 New API

## 目标与分类

新增功能（MINOR），目标版本 `0.107.0-dev.1`。在已有 CPA-Manager-Plus、Codex Proxy 之外增加 New API 数据源，独立保存地址与有 `usage:read` 权限的面板个人访问令牌，可切换、测试连接并查看今天、昨天、近 7 天、近 30 天的用量。

## 接口与数据约束

- New API 的 `GET /api/data/self` 按小时返回当前用户的 `count`、`token_used`、`quota`、`cache_read_tokens`、`cache_creation_tokens` 与 `model_name`。使用 `start_timestamp` 和 `end_timestamp` 查询，面板个人访问令牌（`nap_...`）通过 Bearer 头认证。`GET /api/status` 提供 `quota_per_unit` 和 `enable_data_export`。
- 后端只代理这两个固定路径，避免网页跨域和把令牌放进 URL。只接受 http(s) 地址，限制超时、响应体大小并禁止重定向；上游错误不回显令牌。
- 汇总接口不区分输入与输出 Token，也不包含失败请求。按模型和时间段汇总实际字段；不把未知字段当成真实的零。金额由上游额度除以上游 `quota_per_unit` 得出。
- 上游按整点聚合并周期性写库，当前小时数据可能延迟；若关闭数据导出，应提示用户开启。用户配置的日志查询最大天数可能小于近 30 天，届时显示上游错误，不伪装为零用量。

## 实施步骤

1. 扩展浏览器配置，保留已有数据源配置和选择状态；设置页增加 New API 地址、个人访问令牌与连通性测试。
2. 增加配对鉴权保护的后端固定接口代理，并验证请求边界、认证和错误输出。
3. 把 New API 数据转换为现有统计面板格式，增加来源切换、总量与请求数卡片、趋势及模型明细，给出数据延迟说明。
4. 更新版本和简要变更记录，运行有针对性的验证与网页构建，最后本地提交。未经明确要求不推送。

## 验收

- 旧数据源设置保持可用；切换来源后各自读取自己的配置。
- New API 的连通性测试检查授权与统计开关；正确显示上游时段内的总 Token、请求数、金额、缓存量、趋势和模型明细。
- 无效地址、凭证、上游异常和不完整数据有明确提示，不把凭证暴露在错误中。
